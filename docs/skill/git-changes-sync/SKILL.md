# Git, changes, and sync

## When to use
- Writing or reviewing anything in `internal/git/` (command, branch, publish, manifest, sync, refs).
- Implementing `cowflow change publish|list|show|manifest|discard`, `cowflow sync`, `cowflow sync status|abort`, `cowflow index rebuild`, `cowflow who --path`.
- Implementing `POST /v1/changes/publish`, `/v1/changes/{id}[/manifest|/discard]`, `/v1/sync-requests[/{id}/apply|/abort]`, or MCP `cowflow_publish_change`, `cowflow_list_changes`, `cowflow_request_sync`.
- Touching tables `changes`, `change_files`, `sync_attempts`, `path_index`, `contract_refs`, `change_ancestry`.
- Not for: integration groups/promotion (see `integration-engine`), workspace creation (`internal/workspace`).

## Rules
Invocation
- MUST call git via `exec.Command` (context-bound) with `-C <dir>`, `GIT_TERMINAL_PROMPT=0`, and a timeout (§8.1). NEVER build a shell string or use `cmd.exe`/`sh -c`; arguments are arrays (§7, §17).
- MUST require `git >= 2.40`; it is the only runtime dependency (§3.1). `cowflow doctor` reports it.
- MUST sanitize every branch/ref name with `git check-ref-format` before use (§17).
- MUST treat Git as canonical history; SQLite holds metadata, events, derived indexes (§2.2.6). Reconciliation reads the actual Git and filesystem (§17, §18).
- Git is a swappable interface (`GitProvider`, §1.1, §2.2.9).

Branches and refs
- One branch per task: `cowflow/<project>/<task-slug>` (§8.1). Under the `gitflow` preset, `task create --kind feature|bugfix|chore|hotfix|release` generates `<kind>/<slug>` and rejects non-conforming names (§24.2) — see Pitfalls.
- Refs are global state; minimize them: one retention ref per change, one branch per task (§2.2.13).
- Publishing creates `refs/cowflow/changes/<id>` (namespace `[git].shared_ref_namespace`) and NEVER merges into the target (§8.1, §22).
- Workspaces are never created on `main`/`develop`; `change publish` refuses if `HEAD` is on them (§24.2).
- Workers MUST NOT `git push`, `git tag`, delete branches, or touch `refs/cowflow/*` (§24.14). Remote credentials belong to the user only; refs stay local until a Hub exists (§17, §23 decision 8).

Publish
- Refuse publish without an intent (§2.2.3, §15.5, §20.4); refuse with a violated invariant when `check_on_publish = true` (§9.6, §20.4). Refusal is server-side, model-independent; CLI exit `4` (§14).
- `enforce_commit_format = true` → reject non-Conventional-Commit messages with a diagnostic: `<type>(<scope>): <summary>`, types `feat|fix|chore|refactor|test|docs|perf|build|ci`, summary ≤ 72 chars, imperative, no trailing period (§24.3).
- Trailers `Cowflow-Task: <task-id>`, `Cowflow-Change: <change-id>`, and `Cowflow-Request: <id>` when fulfilling a cross-request are generated by COWFlow on publish (§24.3).
- Reject manifests containing `blocked_patterns` (`.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa*`) (§17, §22) or `node_modules/`, `.cowflow/`, `*.log`, build artifacts, `.env*` (§24.13).
- Files outside the intent `paths` → `scope.exceeded` warning in the manifest, not a refusal (§24.9).
- A publish that changes an `agreed` contract without an open `confirm_contract` request is rejected (§24.8).
- NEVER rebase/amend a published commit; a fix is a new commit and new change, the previous one becomes `superseded` automatically (§8.1, §24.3, §24.10).
- Audit every publish/sync (§17). State + event in the same transaction; prefixed ULID IDs (§13). Events: `change.published|superseded|discarded`, `sync.*` (§9.9).

Manifest and index
- Manifest per §8.2: `files[]{path, op, blob_before, blob_after, add, del}`, `stat{files, add, del}`, `touches_contracts[]`. Obtained once with `git diff-tree -r --numstat` + `--raw` (§8.2).
- After publish, overlap, contract impact, and the index MUST work without touching Git (§8.2). `who --path` answers from the index only (§8.3, §20.23).
- `path_index`, `contract_refs`, `change_ancestry` updated in the same transaction as the publish/intent; recomputable via `cowflow index rebuild` (§8.3, §23).

Sync
- Strategies: `merge` (default, `[git].default_sync_strategy`, merges the retention ref, preserves identity), `cherry-pick` (explicit, trailer `x-cowflow-source`), `squash-merge` (explicit, one local commit; CLI `--strategy squash`) (§8.4, §14, §23 decision 7).
- Sync only published changes; never merge a live task's branch (§24.10). Sync is explicit, never invisible/automatic (§2.2.5, §3.2).
- Sync records SHAs and the result (§8.1) and the `--reason` (§24.10).
- Conflict: nothing overwritten; state `conflict` with files; `abort` restores (§18, §20.5). CLI exit `3` on conflict (§14).
- The agent does not choose `workspace_id`; `cowflow_request_sync` syncs into the caller's own workspace (§15).

States
- `published → validated → promoted`, or `superseded` / `discarded`; always visible separately (§8.5, §2.2.7, §20.9). A broken published change → `change.discarded` by the lead (§24.10).

## Implementation guide
Layout (§16.1): `internal/git/{command.go, branch.go, publish.go, manifest.go, sync.go, refs.go}`; index tables in `internal/store/` (index); domain types in `internal/domain/`.

```go
// GitProvider name from §1.1; method set is Guidance.
type GitProvider interface {
    Run(ctx context.Context, dir string, args ...string) (stdout []byte, err error)
}
type Change struct { ID, TaskID, SessionID, HeadSHA, BaseSHA, Ref string; State ChangeState; Manifest Manifest }
type ChangeState string // "published" | "validated" | "promoted" | "superseded" | "discarded"
type Manifest struct { Files []FileEntry; Stat Stat; TouchesContracts []string }
type FileEntry struct { Path, Op, BlobBefore, BlobAfter string; Add, Del int }
type SyncStrategy string // "merge" | "cherry-pick" | "squash-merge"
```

Steps
1. `command.go`: `exec.CommandContext(ctx, gitPath, append([]string{"-C", dir}, args...)...)`; env `os.Environ()` + `GIT_TERMINAL_PROMPT=0`; per-call timeout from `command_timeout_seconds`; return typed errors with exit code + stderr. Guidance: set `cmd.WaitDelay`; add `LC_ALL=C` for parseable output; use `--end-of-options`/`--` before user-supplied refs/paths; resolve SHAs with `rev-parse --verify <x>^{commit}`.
2. Version gate: parse `git version` (Windows suffix `.windows.N`) and compare ≥ 2.40.
3. `refs.go`: validate with `git check-ref-format` (`--branch` for branch names). Guidance: create retention refs with `git update-ref <ref> <sha> ""` (empty old value = must not exist) so creation is atomic and idempotent per change ID.
4. `manifest.go`: one `git diff-tree -r -z --raw --numstat <from> <to>` call; parse raw records (modes, blobs, status) and numstat (`-` for binary). `touches_contracts` = paths under `contracts/` (§24.8). Guidance: map status letters to `op`; the spec only shows `"modify"`.
5. `publish.go` (order): authorize session → intent exists → branch not `main`/`develop` → resolve `HEAD` → commit format + trailers → manifest → blocked/forbidden paths → contract rule → `check_on_publish` invariants → retention ref → one SQLite tx: `changes`, `change_files`, `change_ancestry`, `path_index`, `contract_refs`, supersede previous change of the task, outbox `change.published` (+ `change.superseded`), `audit_log`.
6. `sync.go`: record pre-sync `HEAD`; apply strategy into the target workspace; on conflict list files (`git diff --name-only --diff-filter=U`), persist `sync_attempts` state `conflict`, emit `sync.*`; `abort` → `git merge --abort` / `git cherry-pick --abort` / restore recorded `HEAD` (Guidance). Cherry-pick adds trailer `x-cowflow-source` (Guidance: `git commit --trailer`).
7. Idempotency: every mutating op carries an `op_id` so a daemon restart can reconcile Git × SQLite (§18, §23).

## Pitfalls
- Branch pattern: §8.1 (`cowflow/<project>/<task-slug>`) vs §24.2 gitflow (`<kind>/<slug>`) — the active `[conventions].preset` decides; do not hardcode one.
- Manifest diff base (`base_sha` vs previous change head vs parent commit) is not specified; ask before deciding. Same for `x-cowflow-source` value and how publish-time trailers coexist with an immutable commit.
- Whether a non-descendant `HEAD` (rewritten history) is refused or just becomes a new change is not specified beyond §8.1.
- Retention GC after `change_retention_days` is not specified for promoted/superseded changes — do not delete refs still referenced by an integration group.
- `who --path` and overlap MUST NOT shell out to git (verified by mock, §20.23).
- Windows: `core.longpaths=true`, `core.autocrlf=false` per worktree, `.gitattributes` `* text=auto eol=lf` (`require_gitattributes`) (§7, §22); paths canonicalized and confined (§7, §12).
- Ref creation and the SQLite tx are not atomic together; reconciliation must handle a ref without a row and vice versa.
- Never parse porcelain output without `-z`; filenames may contain spaces/newlines.

## Tests required
- Unit: arg construction (no shell, `-C`, env), version parse, `check-ref-format` rejections, commit-format validator, manifest parser (fuzz, §18.1), status mapping, binary numstat.
- Harness (§18.1): Git repo on tmpfs; fault injection into the Git subprocess (exit code, timeout, truncated output) for publish/manifest/sync; daemon crash between outbox write and delivery; fake clock for timeouts.
- §18 rows: Sync conflict (nothing overwritten, `conflict` with files, `abort` restores); Daemon restarts (idempotent `op_id`).
- §20: 1 (independent branches), 3 (attributable by task/session via trailers), 4 (publish refused without intent / with violated invariant), 5 (merge with recorded conflict), 9 (states distinct), 15 (no event duplication/loss), 23 (`who --path` without Git, mock), 31 (gitflow: non-conforming branch refused; agent commit to `main`/`develop` refused).
- Concurrency: 20+ sessions publishing in parallel with `-race`; supersede chain correct in `change_ancestry`; `index rebuild` reproduces incremental tables.

- [ ] Previous change auto-`superseded`; no amend/rebase path exists.
